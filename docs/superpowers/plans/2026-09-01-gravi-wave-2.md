## Why S6 and S10 are not in this wave

**S6 (entities and archetypes)** wants `sim.py` for node lifetime and
depletion. So does S8. The map's own rule is that a `sim.py` conflict between
two sessions costs more than the wait, and nothing about S6 is urgent enough to
break it.

S6 also **needs re-scoping before it starts.** Its charter lists charged
surfaces as in-scope, but those shipped on 2026-08-22 as part of slice 2.
Whoever expands S6 into a task plan must diff the charter against what is
actually built, or the session will re-implement finished work.

**S10 (path map)** is not merely a file overlap — it has a sequencing
dependency. `pathmap.py` renders the route *at end of run*, and end-of-run
becomes S8's `summary.py` scene. S10 has nowhere to draw until that seam
exists.

Both start as wave 3, once S8 lands.

## The failure this wave is most likely to produce

S8 edits `sim.py` while S7 measures difficulty against it. S8's plan says its
run-log change is "emit hooks only — no behaviour change". If that slips —
a reordered step, a moved force application, a changed collision result — every
number S7 bakes is quietly wrong, and **both sessions stay green the whole
time**, because each is individually correct. The library only reveals itself
as fiction during playtesting, which is the most expensive place to find it.

Two mitigations, both cheap:

1. **S8 lands its `sim.py` hooks first**, as one identifiable commit, before S7
   bakes anything.
2. **S7 records the `sim.py` commit SHA** its library was measured against, in
   the library itself. A stale library must be obvious rather than remembered
   (map invariant 2).

## Definition of done for the wave

- S5's spec is merged and S6, S9 can be expanded from it without further design.
- S7 has a difficulty measurement that runs headless in CI, and a baked library
  stamped with the `sim.py` SHA it was measured against.
- S8 has `main.py` reduced to a pump, scenes as an explicit state machine, and
  a run event log that S5 and S9 can consume.
- The full suite passes on `main` with all three merged, and the live page still
  boots — the deploy is automatic now, so a bad merge publishes itself.
